# 快速上手指南

> 面向新加入的测试开发人员。从环境搭建到写出第一个测试用例,目标 30 分钟内跑通。

## 1. 环境搭建

### 1.1 前置要求

- Python 3.12+
- uv(依赖管理工具)
- Git
- PyCharm(推荐)或 VS Code
- 系统已装 Chrome(真实浏览器测试用)

### 1.2 安装 uv

```powershell
# Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# Linux/Mac
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 1.3 克隆并初始化

```powershell
git clone <repo-url> automation-platform
cd automation-platform
uv sync                 # 创建 .venv,安装 framework + 全部依赖
```

`uv sync` 会自动:
- 创建平台级 `.venv`(所有项目共享)
- 以 editable 模式安装 `framework`(workspace 成员)
- 安装 pytest / ruff / mypy 等开发依赖

### 1.4 PyCharm 配置

1. **打开项目**: File -> Open -> 选 `automation-platform` 目录
2. **解释器**: Settings -> Project -> Python Interpreter -> Existing:
   ```
   C:\work\PythonProject\automation-platform\.venv\Scripts\python.exe
   ```
   选 `python.exe`,不是 `pytest.exe`。不要选 `projects/<system>/.venv`(空壳)。
3. **测试运行器**: Settings -> Tools -> Python Integrated Tools -> Default test runner: pytest
4. **标记源码根**(可选): 右键 `framework/src` -> Mark Directory as -> Sources Root

## 2. 项目结构速览

```
automation-platform/
├── framework/src/framework/    # 共享框架(不要改,除非加公共能力)
│   ├── core/                   # 配置/日志/上下文/异常
│   ├── clients/                # HTTP/Web/App/DB/Cache/MQ 客户端
│   ├── testing/                # 数据驱动/接口依赖/断言/提取/hooks
│   ├── reporting/              # Allure 报告扩展
│   └── plugins/ai/             # AI 失败分析
├── projects/                   # 业务测试工程(你的工作区)
│   ├── template/               # 模板(复制即用)
│   ├── jmseg/                  # JMS 埃及(API 自动化)
│   ├── jmseu/                  # JMS 德国(WebUI 自动化)
│   ├── oms/  wms/  tms/        # 其他业务系统
├── tests/                      # framework 自身测试
├── docs/                       # 文档
├── scripts/ci/                 # CI 统一入口
└── pyproject.toml              # 根配置(uv workspace)
```

**核心概念**: `framework` 是共享内核,`projects/` 下每个文件夹是一个独立业务系统。
你的日常工作在 `projects/<系统>/` 里,不需要改 `framework`(除非加公共能力)。

## 4. 写第一个 API 测试用例

以 `projects/template` 为例,演示完整流程。

### 4.1 接口封装(api/)

```python
# projects/template/api/login.py
from framework.clients.http.auth import Token
from framework.clients.http.client import AsyncHttpClient

class LoginApi:
    """登录接口封装."""

    def __init__(self, client: AsyncHttpClient) -> None:
        self._client = client

    async def login(self, username: str, password: str) -> Token:
        resp = await self._client.post(
            "/login", json={"username": username, "password": password}
        )
        resp.raise_for_status()
        return Token(access_token=resp.json["access_token"])
```

### 4.2 测试用例(testcase/)

```python
# projects/template/testcase/test_login.py
import pytest
from api.login import LoginApi
from framework.clients.http.client import AsyncHttpClient

@pytest.mark.smoke
async def test_login_returns_token(http_client: AsyncHttpClient) -> None:
    token = await LoginApi(http_client).login("demo", "demo123")
    assert token.access_token == "mock-token-xyz"
```

### 4.3 数据驱动用例

```yaml
# projects/template/data/users_cases.yaml
cases:
  - id: create_alice
    name: alice
    email: alice@test.com
  - id: create_bob
    name: bob
```

```python
# projects/template/testcase/test_users.py
from pathlib import Path
import pytest
from framework.testing.datadriven import case_ids, load_cases

_CASES = load_cases(Path(__file__).parent.parent / "data" / "users_cases.yaml")

@pytest.mark.regression
@pytest.mark.parametrize("case", _CASES, ids=case_ids(_CASES))
async def test_create_user(api_client, case: dict) -> None:
    user = await UsersApi(api_client).create_user(case["name"], case["email"])
    assert user["name"] == case["name"]
```

### 4.4 fixture(fixture/)

fixture 提供测试用的客户端。默认用 mock,对接真实环境时改 `base_url`:

```python
# projects/template/fixture/clients.py
@pytest.fixture
async def http_client(mock_transport) -> AsyncIterator[AsyncHttpClient]:
    async with AsyncHttpClient(
        settings=HttpSettings(base_url=API_BASE_URL),  # 改成真实地址
        transport=mock_transport,  # 对接真实环境时删掉这行
    ) as client:
        yield client
```

## 5. 写第一个 WebUI 测试用例

以 `projects/jmseu` 为例。

### 5.1 Page Object(pages/)

```python
# pages/login_page.py
from pages.base_page import BasePage

class LoginPage(BasePage):
    USERNAME_INPUT = "input[placeholder='请输入员工编号']"
    LOGIN_BUTTON = "button:has-text('登录')"

    async def login(self, username: str, password: str) -> None:
        await self._client.fill(self.USERNAME_INPUT, username)
        await self._client.fill(self.PASSWORD_INPUT, password)
        await self._client.click(self.LOGIN_BUTTON)
```

### 5.2 测试用例(testcase/)

```python
# testcase/test_login_web.py
from pages.login_page import LoginPage
from framework.reporting.allure import step

@pytest.mark.smoke
async def test_login_normal_scenario(web_client, base_url, case) -> None:
    login_page = LoginPage(web_client, base_url=base_url)
    with step("打开登录页"):
        await login_page.open()
    with step("登录"):
        await login_page.login(case["username"], case["password"])
    with step("验证"):
        await login_page.wait_for_login_success()
```

### 5.3 假页面 vs 真实浏览器

| 模式 | 触发条件 | 用途 |
| --- | --- | --- |
| 假页面(FakePage) | 默认 | CI/本地快速验证逻辑,无浏览器无网络 |
| 真实浏览器 | `JMSEU_REAL_BROWSER=1` | 对接真实站点,人工解验证码 |

真实浏览器模式在 PyCharm 运行配置里加环境变量:
```
JMSEU_REAL_BROWSER=1
APP_ENV=test
```

`channel=chrome` 和 `headless=false` 已内置在 `config/envs/test.yaml`。

## 6. 常用命令

```powershell
# 跑测试
uv run pytest                              # 全量
uv run pytest -m smoke                     # 只冒烟
uv run pytest -n auto                      # 并发
uv run pytest projects/jmseu/              # 指定项目
uv run pytest -k test_login                # 按名过滤

# 代码质量
uv run ruff check .                        # 静态检查
uv run ruff format .                       # 格式化
uv run ruff check --fix . && uv run ruff format .  # 一键修复
uv run mypy                                # 类型检查

# 依赖
uv sync                                    # 安装/同步依赖
uv add <package>                           # 加依赖
uv export --frozen -o requirements.txt     # 导出 requirements.txt
```

## 7. 调试技巧

### 7.1 PyCharm 断点调试

1. 在测试函数旁点绿按钮 -> Debug(不是 Run)
2. 断点会停在标记行,可查看变量、步进

### 7.2 查看日志

框架用 loguru,日志同时输出到控制台和文件:

```
projects/<system>/logs/app.log    # 项目级日志
```

### 7.3 失败截图

WebUI 测试失败时自动截图(通过 `screenshot_provider` fixture)。
真实浏览器模式还有 `captcha_debug.png` 诊断截图。

### 7.4 Allure 步骤

用 `with step("步骤名"):` 包裹业务步骤,Allure 报告里会显示结构化步骤:

```python
with step("打开登录页"):
    await login_page.open()
with step("输入凭据"):
    await login_page.login(user, pwd)
```

## 8. 常见问题

**Q: `ModuleNotFoundError: No module named 'framework'`**
A: 没用 workspace venv。确认解释器指向 `automation-platform/.venv/Scripts/python.exe`,
   并在项目 `pyproject.toml` 里有 `[tool.uv.sources] framework = { workspace = true }`。

**Q: `Executable doesn't exist at ...chromium_headless_shell`**
A: Playwright 找不到浏览器。在 `config/envs/test.yaml` 配 `channel: chrome` 走系统 Chrome,
   或运行 `playwright install chromium`。

**Q: `uv run` 报 `framework was not found in the package registry`**
A: 项目没加入 uv workspace。在根 `pyproject.toml` 的 `[tool.uv.workspace] members` 加项目路径,
   并在项目 `pyproject.toml` 启用 `[tool.uv.sources] framework = { workspace = true }`。

**Q: 测试被 SKIPPED**
A: 看跳过原因。`test_login_real_browser` 默认 skip,需设 `JMSEU_REAL_BROWSER=1`。

**Q: `pkg_resources` / `setuptools` 报错**
A: PyCharm 测试运行器需要 setuptools<81(v83 移除了 pkg_resources)。根 `pyproject.toml`
   dev 依赖已含 `setuptools<81`,确保 `uv sync` 已执行。
