## 1. 引言

### 1.1 编写目的

本文档描述 **测试管理平台后端**(server/)的概要设计, 面向项目经理、架构师、
开发工程师和测试工程师. 读者通过本文档可理解后端系统的整体架构、模块划分、
接口关系和关键技术选型, 并据此进行扩展开发或集成对接.

配套文档:

- 详细设计: `docs/详细设计文档.md`
- 技术方案(含演进规划): `docs/测试管理平台技术方案.md`
- 运维部署: `docs/部署与运维.md`

### 1.2 项目背景

自动化用例已覆盖多国 WebUI (jmseu / jmsco / jmsmx) 与巴西接口压测 (loadtest),
但执行入口长期依赖 PyCharm 与命令行, 不写代码的测试人员难以独立使用.

本平台定位为"测试工作台": 让测试人员通过 Web 界面完成 项目查询 / 用例查询 /
测试执行 / 报告查看 四个动作, 不再需要直接操作命令行.

平台**不是 CI 调度中心**: 不做权限控制、定时调度、远程分发, 这些能力由
GitLab CI / Jenkins 承担. 平台只在本地拉起 pytest 子进程并展示结果.

### 1.3 术语与缩略语

| 术语        | 全称              | 说明                                                 |

## 2. 系统总体设计

### 2.1 设计目标

| 目标           | 说明                                                                |
| -------------- | ------------------------------------------------------------------- |
| 降低使用门槛   | 测试人员无需命令行/IDE 经验, 浏览器即可触发测试与查看报告           |
| 不侵入现有用例 | 通过 `subprocess` 调用 pytest, 保留原有运行方式与目录结构            |
| 实时进度可观测 | pytest 输出逐行推送至前端, 测试人员无需等待结束才看结果              |
| 数据可追溯     | 执行记录与报告快照持久化到 MySQL, 容器/进程重启不丢历史             |
| 单机零依赖     | 除 MySQL 外不依赖其他外部服务, 部署在一台开发机即可                 |

### 2.2 系统边界

```
   ┌──────────────────┐
   │ 测试人员 (浏览器) │
   └────────┬─────────┘
            │ HTTP + WebSocket
   ┌────────▼─────────────────────────────────────┐
   │   测试管理平台 (本文档范围)                   │
   │   ├─ FastAPI 后端 (server/)                  │
   │   └─ Vue 3 前端 (frontend/, 独立文档)         │
   ├────────┬─────────────────┬───────────────────┤
   │        │                 │                   │
   │   ┌────▼────┐    ┌───────▼──────┐  ┌─────────▼────────┐
   │   │ 文件系统 │    │ pytest 子进程│  │ MySQL 元数据库   │
   │   │projects/│    │ (.venv)      │  │ (执行/报告快照)  │
   │   └─────────┘    └──────┬───────┘  └──────────────────┘
   │                         │
   │                  ┌──────▼───────┐
   │                  │ allure-results│
   │                  │ (JSON 文件)   │
   │                  └──────────────┘
   │
   └────────────────────────────────────────────────┘
            (本机范围, 不出网)
```

**不在范围内**:

- 远程执行节点分发 (后续演进项)
- 用户权限/SSO (本机内网, 团队共享)
- CI 调度 (由 GitLab CI / Jenkins 承担)
- 测试数据管理 UI (用例数据 YAML 由开发维护)

### 2.3 总体架构

### 2.3.1 分层架构

```
┌──────────────────────────────────────────────────────────┐
│ 表现层: frontend/  Vue 3 + Element Plus + ECharts        │
│  - Dashboard / TestCases / Execution / Reports            │
├──────────────────────────────────────────────────────────┤
│ 接口层: server/routers/  FastAPI Router                  │
│  - projects.py / cases.py / executions.py / reports.py   │
├──────────────────────────────────────────────────────────┤
│ 服务层: server/services/  业务逻辑                        │
│  - scanner (项目/用例扫描) / runner (pytest 执行器)      │
│  - allure_parser (报告解析)                              │
├──────────────────────────────────────────────────────────┤
│ 数据层: server/db.py  SQLAlchemy 2.0 async              │
│  - ProjectRow / TestCaseRow / ExecutionRow / ReportRow   │
└──────────────────────────────────────────────────────────┘
```

### 2.3.2 模块职责

| 模块                  | 职责                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `server/main.py`      | FastAPI 应用入口, lifespan 钩子初始化数据库 + 同步项目列表, CORS, 路由聚合                |
| `server/db.py`        | 异步 engine / session 工厂, 4 张元数据表 ORM 模型, upsert / 同步函数                     |
| `server/services/scanner.py` | 扫描 `projects/` 发现项目, 解析 README 描述 / 环境列表 / 测试文件清单               |
| `server/services/runner.py`  | pytest 子进程执行器, 内存任务表 + WebSocket 订阅者推送                            |
| `server/services/allure_parser.py` | 解析 `allure-results/*.json` 聚合为统计快照                                    |
| `server/routers/projects.py` | 项目列表 / 详情 API                                                                      |
| `server/routers/cases.py`    | 用例清单 + 数据驱动参数                                                                  |
| `server/routers/executions.py` | 触发执行 / 列表 / 详情 / WebSocket 实时进度                                           |
| `server/routers/reports.py`  | 报告快照查询 / 历史回退                                                                  |

### 2.4 关键技术选型

| 层级         | 选型                          | 说明                                                   |
| ------------ | ----------------------------- | ------------------------------------------------------ |
| Web 框架     | FastAPI 0.110+                | 原生 async, 自动生成 `/docs` OpenAPI 文档              |
| 实时通信     | WebSocket (FastAPI 内置)      | pytest 输出逐行推送, 无需额外消息中间件                |
| ORM          | SQLAlchemy 2.0 async + aiomysql | 异步 engine, 连接池, `pool_pre_ping` 防止断连         |
| 数据库       | MySQL 8.4                     | 持久化元数据, 与项目主依赖统一                         |
| 执行引擎     | asyncio.create_subprocess_exec | 非阻塞子进程, stdout 异步逐行读取                    |
| 配置外置     | 环境变量 `APP_DATABASE_URL`    | 不硬编码, 部署灵活 (rule 10)                           |
| 错误隔离     | try/except SQLAlchemyError      | DB 不可用时文件扫描 API 仍可用, 不影响主流程         |

## 3. 接口设计

### 3.1 REST API

所有接口挂载在 `/api` 前缀下, 完整 OpenAPI 文档: `http://localhost:8900/docs`.

| Method | 路径                                    | 功能                       |
| ------ | --------------------------------------- | -------------------------- |
| GET    | `/api/projects`                         | 项目列表(同时同步到 DB)   |
| GET    | `/api/projects/{name}`                 | 项目详情 + 测试文件清单    |
| GET    | `/api/projects/{name}/cases?env=test`  | 用例列表 + 数据驱动参数    |
| POST   | `/api/executions`                       | 触发一次 pytest 执行       |
| GET    | `/api/executions`                       | 执行记录列表               |
| GET    | `/api/executions/{id}`                  | 单次执行详情               |
| WS     | `/api/ws/executions/{id}`               | 实时进度推送              |
| GET    | `/api/projects/{name}/report`           | 项目最近报告快照           |
| GET    | `/api/health`                           | 健康检查(DB 可达性)       |

### 3.2 WebSocket 协议

服务器向客户端推送 JSON 消息, 客户端只接收不发数据:

```json
{ "event": "started",  "cmd": "..." }
{ "event": "output",   "line": "..." }
{ "event": "finished", "status": "passed|failed", "returncode": 0 }
{ "event": "done",     "status": "passed|failed" }
```

前端连接后通过 1s 超时的 `queue.get()` 轮询, 检测到任务结束发送 `done` 后断开.

## 4. 数据库设计

### 4.1 表结构

#### 4.1.1 `projects` 项目元数据

| 字段          | 类型         | 约束             | 说明                          |
| ------------- | ------------ | ---------------- | ----------------------------- |
| id            | INT          | PK, AUTO_INC     |                               |
| name          | VARCHAR(100) | UNIQUE, INDEX    | 项目文件夹名 (如 jmseu)       |
| description   | TEXT         |                  | 来自 README 首行              |
| envs          | JSON         |                  | 可用环境列表 (`["test","uat"]`) |
| case_count    | INT          |                  | 用例文件数                    |
| synced_at     | DATETIME     |                  | 最后同步时间                  |

#### 4.1.2 `test_cases` 用例缓存

| 字段          | 类型         | 约束             | 说明                              |
| ------------- | ------------ | ---------------- | --------------------------------- |
| id            | INT          | PK, AUTO_INC     |                                   |
| project_name  | VARCHAR(100) | INDEX            | 关联 projects.name               |
| case_id       | VARCHAR(500) | UNIQUE, INDEX    | `path::function` 形式             |
| file          | VARCHAR(500) |                  | 相对项目根的测试文件路径          |
| name          | VARCHAR(200) |                  | 测试函数名                        |
| description   | TEXT         |                  | 函数 docstring 首行               |
| tags          | JSON         |                  | pytest marker 列表                |
| data_driven   | BOOLEAN      |                  | 是否有 YAML 数据驱动               |
| data_cases    | JSON         |                  | 参数化用例列表                    |
| synced_at     | DATETIME     |                  | 最后同步时间                      |

#### 4.1.3 `executions` 执行记录

| 字段         | 类型         | 约束             | 说明                              |
| ------------ | ------------ | ---------------- | --------------------------------- |
| id           | VARCHAR(32)  | PK               | UUID 前 8 位                      |
| project      | VARCHAR(100) | INDEX            | 项目名                            |
| env          | VARCHAR(50)  |                  | `APP_ENV` 值                      |
| test_paths   | JSON         |                  | pytest 位置参数                   |
| status       | VARCHAR(20)  | INDEX            | pending/running/passed/failed     |
| started_at   | DATETIME     |                  | 开始时间                          |
| finished_at  | DATETIME     | NULLABLE         | 结束时间                          |

#### 4.1.4 `report_snapshots` 报告快照

| 字段        | 类型         | 约束             | 说明                              |
| ----------- | ------------ | ---------------- | --------------------------------- |
| id          | INT          | PK, AUTO_INC     |                                   |
| project     | VARCHAR(100) | INDEX            | 项目名                            |
| total/passed/failed/broken/skipped | INT | | 统计计数 |
| cases       | JSON         |                  | 每个用例的状态/耗时/标签          |
| created_at  | DATETIME     | INDEX            | 快照时间(取最新一次作为当前报告)  |

### 4.2 数据生命周期

- **项目/用例缓存**: 每次 `GET /api/projects` 或 `/api/projects/{name}/cases` 时重新扫描并 upsert
- **执行记录**: 触发执行即 insert, 状态变化时 update, 永久保留(无 TTL)
- **报告快照**: 每次 `GET /report` 时若 `allure-results/` 有内容则 insert 新行, 历史快照不删除

## 5. 关键流程

### 5.1 触发测试执行

```
Browser ──POST /api/executions──▶ executions.create_execution()
                                      │
                                      ├─ runner.create_execution(): 生成 UUID, 写内存 + DB
                                      ├─ asyncio.create_task(runner.run_execution())
                                      │     │
                                      │     ├─ subprocess.Popen("pytest ...", cwd=projects/<name>)
                                      │     ├─ async for line in proc.stdout:
                                      │     │     _notify(execution_id, {"event":"output","line":line})
                                      │     └─ proc.wait(): 状态 → passed/failed
                                      │
                                      └─ 返回 execution_id

Browser ──WS /api/ws/executions/{id}──▶ executions.ws_execution()
                                          │
                                          └─ runner.subscribe(): 注册回调
                                             queue.get(timeout=1s) 轮询, 推送到 WS
```

### 5.2 报告查询(空结果回退)

```
GET /api/projects/{name}/report
        │
        ├─ allure_parser.parse_project_results()
        │     └─ 扫描 projects/<name>/allure-results/*.json
        │        聚合 total/passed/failed/broken/skipped + cases[]
        │
        ├─ if total > 0:
        │     save_report() 写新快照
        │     返回最新结果
        ├─ else:
        │     latest_report() 从 DB 取上次历史快照
        │     返回缓存或空报告
```

## 6. 非功能性设计

### 6.1 错误隔离

所有数据库调用都包在 `try/except (RuntimeError, SQLAlchemyError)` 内, DB 不可用时:

- 文件扫描 API (`/projects`, `/cases`) 继续工作
- 执行 API 退化为纯内存模式 (`runner.list_executions()` 返回内存任务)
- 报告 API 返回空结构让前端显示 "暂无数据"

### 6.2 资源管理

- `lifespan` 钩子: 启动时 `init_db()` + `sync_projects`, 关闭时 `dispose_db()` 释放连接池
- 子进程: `asyncio.create_subprocess_exec` 启动, `proc.wait()` 等待退出, 不留僵尸
- WebSocket: 客户端断开抛 `WebSocketDisconnect`, 自动出订阅者列表

### 6.3 部署形态

- 单机部署: 一台开发机同时跑 FastAPI + Vue dev server + MySQL 容器
- 一键启动脚本: `scripts/start_all.ps1` 自动拉起 MySQL 容器 + 后端 + 前端
- 端口约定: 后端 8900, 前端 5173, MySQL 3306
- CORS: 允许 `http://localhost:5173` 与 `http://127.0.0.1:5173`

## 8. 部署与运行

详见 `docs/部署与运维.md`, 核心命令:

```powershell

scripts/start_backend.ps1    # 终端 1: uvicorn server.main:app --port 8900
```
