# 用户手册

> 面向测试人员与测试开发人员的完整操作手册。覆盖环境配置、测试运行、
> 新增系统、数据驱动、接口依赖、报告生成与日常维护。

## 1. 环境配置

### 1.1 环境分级

平台支持四套环境,通过 `APP_ENV` 环境变量切换:

| 环境 | APP_ENV | 用途 |
| --- | --- | --- |
| 开发 | `dev` | 本地开发(默认) |
| 测试 | `test` | 测试环境验证 |
| 预发 | `uat` | 预发布验证 |
| 生产 | `prod` | 生产环境(慎用) |

### 1.2 配置文件

每个业务项目有自己的 `config/envs/<env>.yaml`:

```yaml
# projects/jmseu/config/envs/test.yaml
env: test
web:
  base_url: https://jmseu-jms.jnt-express.com.cn
  browser: chromium
  headless: false
  channel: chrome          # 走系统 Chrome,免装 playwright 浏览器
  timeout_ms: 30000
  ignore_https_errors: true
```

### 1.3 配置优先级

从高到低:

1. 代码传参 `FrameworkSettings(...)`
2. 环境变量 `APP_*`(嵌套用 `__`,如 `APP_WEB__HEADLESS=false`)
3. `.env` 文件(平台根目录)
4. `config/envs/<APP_ENV>.yaml`
5. 模型默认值

### 1.4 敏感信息(.env)

账号密码等敏感信息放 `.env`(已被 .gitignore 忽略,不会提交):

```
# automation-platform/.env
APP_ENV=test
JMSEU_TEST_USERNAME=01943937
JMSEU_TEST_PASSWORD=<密码>
```

项目的 `conftest.py` 会用 `python-dotenv` 从平台根加载 `.env`。

### 1.5 新机器初始化

```powershell
git clone <repo> automation-platform
cd automation-platform
uv sync                                  # 创建 .venv + 安装依赖
# PyCharm: 解释器选 .venv\Scripts\python.exe
# 可选: playwright install chromium(或用 channel: chrome 走系统 Chrome)
```

## 2. 运行测试

### 2.1 命令行

```powershell
# 全量
uv run pytest

# 按标记
uv run pytest -m smoke                    # 冒烟(快速门禁)
uv run pytest -m regression               # 回归(全量)

# 按项目
uv run pytest projects/jmseu/             # 指定项目
uv run pytest projects/jmseu/testcase/test_login_web.py  # 指定文件

# 按名称
uv run pytest -k test_login               # 名字包含 test_login
uv run pytest -k "test_login and not real_browser"  # 组合过滤

# 并发
uv run pytest -n auto                     # 自动按 CPU 核数并行
uv run pytest -n 4                        # 指定 4 进程

# 详细输出
uv run pytest -v                          # 每个用例一行
uv run pytest -s                          # 显示 print/日志
uv run pytest --tb=long                   # 完整 traceback
```

### 2.2 PyCharm

1. 解释器: `automation-platform/.venv/Scripts/python.exe`
2. 右键测试文件/函数 -> Run / Debug
3. 运行配置里加环境变量(真实浏览器测试需要):

```
JMSEU_REAL_BROWSER=1
APP_ENV=test
```

### 2.3 CI/CD

CI 通过 `scripts/ci/ci.sh` 统一入口:

```bash
sh scripts/ci/ci.sh install      # 安装依赖
sh scripts/ci/ci.sh smoke        # 冒烟测试
sh scripts/ci/ci.sh regression   # 回归测试
sh scripts/ci/ci.sh report       # 生成 Allure 报告
```

GitLab CI(`.gitlab-ci.yml`)和 Jenkins(`Jenkinsfile`)都调用这个脚本,避免命令重复。

### 2.4 真实浏览器测试(WebUI)

WebUI 测试有两种模式:

| 模式 | 触发 | 用途 |
| --- | --- | --- |
| 假页面 | 默认 | CI/快速验证,无浏览器 |
| 真实浏览器 | `JMSEU_REAL_BROWSER=1` | 对接真实站点 |

真实浏览器模式:
1. `.env` 配置账号密码
2. `config/envs/test.yaml` 配 `base_url` + `channel: chrome` + `headless: false`
3. 设 `JMSEU_REAL_BROWSER=1` + `APP_ENV=test`
4. 运行测试,浏览器自动打开走登录流程
5. 验证码出现时人工滑动,脚本检测到成功标志即通过

## 3. 新增业务系统

### 3.1 复制模板

```powershell
Copy-Item -Recurse projects/template projects/<新系统名>
```

### 3.2 修改配置

1. `projects/<新系统>/pyproject.toml`: 改 `name`
2. 根 `pyproject.toml`: `[tool.uv.workspace] members` 加 `"projects/<新系统>"`
3. `projects/<新系统>/config/envs/*.yaml`: 配 `base_url` 等

### 3.3 conftest.py

确保 `conftest.py` 做了三件事:

```python
# 1. 定位配置目录
os.environ.setdefault("APP_CONFIG_DIR", str(Path(__file__).parent / "config" / "envs"))
os.environ.setdefault("APP_ENV", "dev")

# 2. 启用框架 pytest 插件
pytest_plugins = ["framework.testing.hooks.fixtures"]

# 3. re-export 项目 fixtures
from fixture.clients import http_client, api_client  # noqa: F401
```

### 3.4 编写代码

- API 项目: `api/`(接口封装) + `testcase/`(用例) + `data/`(数据) + `fixture/`(客户端)
- WebUI 项目: `pages/`(Page Object) + `testcase/`(用例) + `data/`(数据) + `fixture/`(客户端)

### 3.5 验证

```powershell
cd projects/<新系统>
..\..\.venv\Scripts\python.exe -m pytest -v
```

## 5. 数据驱动

### 5.1 YAML 数据文件

```yaml
# data/login_cases.yaml
cases:
  - id: normal_admin
    description: 管理员正常登录
    username: admin
    password: Admin@123
    expected_welcome_contains: admin
  - id: wrong_password
    description: 密码错误
    username: admin
    password: wrong
    expected_error: 密码错误
```

### 5.2 测试用例

```python
from pathlib import Path
import pytest
from framework.testing.datadriven import case_ids, load_cases

_CASES = load_cases(Path(__file__).parent.parent / "data" / "login_cases.yaml")

@pytest.mark.parametrize("case", _CASES, ids=case_ids(_CASES))
async def test_login(case: dict[str, Any]) -> None:
    ...
```

`case_ids(_CASES)` 用 yaml 里的 `id` 字段作为测试名,比默认 `case0/case1` 清晰。

## 6. 接口依赖编排

### 6.1 场景

接口 B 依赖接口 A 的返回值(如创建订单后拿订单号查询详情)。

### 6.2 用法

```python
from framework.testing.dependency import DAG, VariableManager

# 定义依赖图
dag = DAG()
dag.add("create_order", depends_on=[])
dag.add("query_detail", depends_on=["create_order"])

# 执行
variables = VariableManager()
async def create_order():
    resp = await client.post("/orders", json={...})
    variables.set("order_id", resp.json["id"])

async def query_detail():
    order_id = variables.get("order_id")
    resp = await client.get(f"/orders/{order_id}")
    assert resp.json["status"] == "created"

dag.bind("create_order", create_order)
dag.bind("query_detail", query_detail)
await dag.execute()
```

## 7. Allure 报告

### 7.1 生成报告

```powershell
# 安装 allure-pytest(CI 镜像已预装)
uv add allure-pytest

# 运行并生成结果
uv run pytest --alluredir=reports/allure-results

# 生成 HTML
allure generate reports/allure-results -o reports/allure-report --clean

# 打开
allure open reports/allure-report
```

### 7.2 步骤与附件

```python
from framework.reporting.allure import step, attach_json, attach_text

with step("登录"):
    await login_page.login(user, pwd)

with step("验证响应"):
    attach_json(resp.json(), name="response")
```

### 7.3 标签

```python
from framework.reporting.labels import severity, feature, story, issue

@severity("critical")
@feature("登录")
@story("正常登录")
@issue("JIRA-123")
async def test_login(): ...
```

## 8. 代码质量

### 8.1 日常检查

```powershell
uv run ruff check .                    # 静态检查
uv run ruff format .                   # 格式化
uv run ruff check --fix . && uv run ruff format .  # 一键修复
uv run mypy                            # 类型检查(strict 模式)
```

### 8.2 提交钩子

```powershell
uv run pre-commit install              # 安装 git hook
# 之后每次 commit 自动跑 ruff check + format
```

### 8.3 规范要求(AI_RULES 16 条摘要)

- 所有函数必须类型声明(第 6 条)
- 不允许复制代码,重复逻辑抽象(第 8 条)
- 修改代码前先分析影响范围(第 9 条)
- 配置与密钥外置,禁止硬编码(第 10 条)
- 资源必须显式释放(第 12 条)
- 单元测试必须隔离外部依赖(第 14 条)
- 框架内禁止 print,统一走 loguru(第 15 条)
- 异步上下文禁止阻塞调用(第 16 条)

## 9. 日常维护

### 9.1 依赖更新

```powershell
uv sync                                # 同步 uv.lock
uv lock --upgrade                      # 升级依赖版本
uv export --frozen -o requirements.txt # 重新导出 requirements.txt
```

### 9.2 新增 framework 能力

1. 在 `framework/clients/<name>/` 或 `framework/testing/<name>/` 创建模块
2. 遵循现有模式(lazy import + async + 类型声明)
3. 配置项加到 `core/config.py`
4. 在 `__init__.py` 导出 + 更新 `__all__`
5. 写单元测试(`tests/unit/`,mock 外部依赖)
6. 更新 `docs/架构设计.md`

### 9.3 留痕记录

每次完成实质任务后,向对应留痕文档追加记录:

| 文档 | 用途 |
| --- | --- |
| `docs/协作留痕.docx` | 框架架构开发 |
| `docs/业务留痕-<国家>.docx` | 各国业务测试 |

留痕格式见 `AGENTS.md` 第 10 条:索引表 + 正文 + 文件变更表 + 验证结果表 + 影响范围表。

### 9.4 故障排查

| 问题 | 排查 |
| --- | --- |
| `ModuleNotFoundError: framework` | 解释器选错,用 `automation-platform/.venv` |
| Playwright 找不到浏览器 | `config/envs/test.yaml` 配 `channel: chrome` |
| `uv run` 找不到 framework | 检查 workspace members + `[tool.uv.sources]` |
| 测试 skip | 看跳过原因,真实浏览器需 `JMSEU_REAL_BROWSER=1` |
| `pkg_resources` 缺失 | `setuptools<81`(v83 移除了 pkg_resources) |
| mypy 报错 | 看错误信息,多数是类型声明缺失或返回值类型不匹配 |
| CI 失败 | 本地跑 `sh scripts/ci/ci.sh smoke` 复现 |
