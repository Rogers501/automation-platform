# 部署与运维

> 项目基础设施的部署/启动/备份/恢复说明. 覆盖 Docker 测试依赖、测试管理平台
> 一键启动、镜像导出与数据持久化.

## 1. 基础设施清单

| 服务 | 用途 | 端口 | 数据持久化 |
| --- | --- | --- | --- |
| MySQL 8.4 | 测试管理平台元数据库 | 3306 | `data/mysql/` |
| Redis 7.4 | 缓存测试 (框架能力) | 6379 | Docker named volume |
| Kafka 3.9 | 消息队列测试 (框架能力) | 9092 | Docker named volume |
| GitLab CE | 部门协同 Git 服务器 | 8929 / 2224 | `C:/docker-data/git-server/` |
| FastAPI (容器) | 测试管理平台后端 | 8900 | - |
| nginx (容器) | 测试管理平台前端 (生产模式) | 8080 | - |

> GitLab 部署独立于本项目, 详见 `docs/GitLab本地部署.md`.
> 容器化部署见 §3.5; 本地开发模式启动见 §3.1-3.3.

## 2. Docker 测试依赖

### 2.1 docker-compose 配置

文件: `docker/docker-compose.yml`, 包含 MySQL / Redis / Kafka 三个服务.

```bash
# 启动全部
docker compose -f docker/docker-compose.yml up -d

# 启动单个
docker compose -f docker/docker-compose.yml up -d mysql

# 停止
docker compose -f docker/docker-compose.yml down

# 看状态
docker compose -f docker/docker-compose.yml ps
```

### 2.2 MySQL 数据持久化

MySQL 数据目录绑定到项目本地 `data/mysql/`:

```yaml
volumes:
  - ../data/mysql:/var/lib/mysql
```

**关键点**:
- Docker Desktop 更新、卸载或容器重建**不会删除**该目录
- `data/mysql/` 已被 `.gitignore` 忽略, 不会进 Git
- 容器首次启动会自动创建数据库 `automation` 与用户 `tester`

### 2.3 默认凭据

| 项 | 值 | 说明 |
| --- | --- | --- |
| Root 密码 | `rootpw` | 仅本地用, 不要暴露到生产 |
| 业务数据库 | `automation` | 测试管理平台用 |
| 业务用户 | `tester` / `testerpw` | 仅授予 automation 数据库权限 |

可通过环境变量覆盖 (见 `.env.example`):

```
MYSQL_ROOT_PASSWORD=rootpw
MYSQL_DATABASE=automation
MYSQL_USER=tester
MYSQL_PASSWORD=testerpw
```

### 2.4 连接 URL

测试管理平台后端默认用:

```
mysql+aiomysql://tester:testerpw@127.0.0.1:3306/automation
```

可通过环境变量 `APP_DATABASE_URL` 覆盖.

## 3. 测试管理平台启动

### 3.1 一键启动 (推荐)

```powershell
# 在项目根目录执行
powershell -ExecutionPolicy Bypass -File scripts/start_all.ps1
```

脚本自动完成:
1. 检查并加载 MySQL 离线镜像 (`data/docker-images/mysql-8.4.tar`)
2. 启动 MySQL 容器并等待健康检查
3. 启动 FastAPI 后端 (`uvicorn server.main:app --port 8900`)
4. 启动 Vite 前端 (`npm run dev --port 5173`)
5. 轮询 `/api/health` 确认后端就绪
6. 输出访问地址

强制 `chcp 65001` + UTF-8 输出, 避免中文乱码.

### 3.2 分进程启动

如需单独调试前后端, 分别开两个 PowerShell 终端:

```powershell
# 终端 1: 后端
powershell -ExecutionPolicy Bypass -File scripts/start_backend.ps1

# 终端 2: 前端
powershell -ExecutionPolicy Bypass -File scripts/start_frontend.ps1
```

参数支持:

```powershell
.\scripts\start_backend.ps1 -Port 8900
.\scripts\start_frontend.ps1 -Port 5173
```

### 3.3 访问入口

| 入口 | 地址 |
| --- | --- |
| 前端工作台 | http://localhost:5173 |
| 后端 API 文档 (Swagger) | http://localhost:8900/docs |
| 健康检查 | http://localhost:8900/api/health |

### 3.4 首次部署

```powershell
# 1. 克隆代码
git clone <repo-url> automation-platform
cd automation-platform

# 2. Python 依赖
uv sync                       # 创建 .venv + 安装 framework + 全部依赖
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt

# 3. 前端依赖
cd frontend
npm install
cd ..

# 4. (可选) 准备 MySQL 离线镜像
.\scripts\save_mysql_image.ps1    # 导出 mysql-8.4.tar 到 data/docker-images/

# 5. 一键启动
.\scripts\start_all.ps1
```

### 3.5 容器化部署 (生产模式, 给同事访问)

本地开发用 §3.1 的 `start_all.ps1` (vite dev + uvicorn 本地进程);
给同事访问用本节 (容器化 + nginx 托管), 性能更好、隔离更彻底.

#### 3.5.1 部署架构

```
同事浏览器 → http://10.66.67.26:8080
                    ↓
              ┌─────────────────────┐
              │ frontend 容器 (nginx)│  8080:80
              │  - 托管 dist 静态文件 │
              │  - /api /ws 反代后端 │
              └────────┬────────────┘
                       ↓
              ┌─────────────────────┐
              │ backend 容器        │  8900
              │  FastAPI + uvicorn  │
              │  含 framework+projects (后端调 pytest 跑测试)
              └────────┬────────────┘
                       ↓
              ┌─────────────────────┐
              │ mysql 容器          │  3306
              │  元数据库 (automation)
              └─────────────────────┘
```

#### 3.5.2 首次部署

```bash
# 前置: 本地已有 python:3.12-slim / node:20-alpine / nginx:alpine 镜像
# 国内拉不下来 docker.io, 用镜像源前缀拉再 retag:
#   docker pull docker.1ms.run/library/python:3.12-slim && docker tag docker.1ms.run/library/python:3.12-slim python:3.12-slim
#   docker pull dockerproxy.net/library/node:20-alpine && docker tag dockerproxy.net/library/node:20-alpine node:20-alpine
#   docker pull docker.1ms.run/library/nginx:alpine && docker tag docker.1ms.run/library/nginx:alpine nginx:alpine

# 构建后端与前端镜像
cd docker
docker compose build backend frontend

# 启动 mysql + backend + frontend (不需要 redis/kafka 时只起这三个)
docker compose up -d mysql backend frontend

# 看状态 (mysql 和 backend 应是 healthy, frontend 是 Up)
docker compose ps
```

#### 3.5.3 访问入口

| 入口 | 地址 |
| --- | --- |
| 前端工作台 (同事访问) | http://10.66.67.26:8080 |
| 后端 API 文档 (Swagger) | http://10.66.67.26:8080/docs (经 nginx 反代) 或 http://localhost:8900/docs (直连) |
| 健康检查 | http://10.66.67.26:8080/api/health |

#### 3.5.4 关键配置

**docker-compose.yml 新增服务** (在 §2.1 的基础上):

| 服务 | 镜像 | 端口 | 关键依赖 |
| --- | --- | --- | --- |
| `backend` | `automation-platform-backend:latest` (本地构建) | 8900 | depends_on mysql (healthy) |
| `frontend` | `automation-platform-frontend:latest` (本地构建) | 8080:80 | depends_on backend (healthy) |

**后端环境变量**:

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `APP_DATABASE_URL` | `mysql+aiomysql://tester:testerpw@mysql:3306/automation` | 连容器内 mysql (不是 127.0.0.1) |
| `APP_CORS_ORIGINS` | `http://10.66.67.26:8080,http://localhost:8080,...` | 允许前端容器 origin 跨域 |

**容器卷**:

| 卷 | 用途 |
| --- | --- |
| `../projects:/app/projects:ro` | 后端只读访问项目代码, 跑 pytest 用 |
| `../allure-report:/app/allure-report` | 测试报告输出 |
| `../data:/app/data` | 数据目录 |

#### 3.5.5 日常运维

```bash
# 启动
cd docker && docker compose up -d mysql backend frontend

# 停止
docker compose down

# 重启单个服务
docker compose restart backend

# 看日志
docker compose logs -f backend
docker compose logs -f frontend

# 代码更新后重建镜像
docker compose build backend frontend
docker compose up -d backend frontend

# 进容器调试
docker compose exec backend bash
docker compose exec frontend sh
```

#### 3.5.6 故障排查

| 现象 | 排查 |
| --- | --- |
| 前端打开是 nginx 502 | backend 没起或还没 healthy, 等 30s 或 `docker compose logs backend` |
| `/api/health` 返回 `database: unavailable` | mysql 容器没 healthy 或 APP_DATABASE_URL 不对 |
| 同事访问 `10.66.67.26:8080` 超时 | Windows 防火墙没放行 8080 端口, 见 §7.6 |
| `docker compose build` 拉 python/node/nginx 失败 | 国内拉不下来 docker.io, 见 §3.5.2 镜像源前缀拉法 |
| 前端 build 报 `node.exe: not found` | npm shim 在 Linux 容器调错, Dockerfile 已用 `node node_modules/vite/bin/vite.js build` 绕过 |
| 后端调 pytest 报 `python.exe: not found` | `server/services/runner.py` 已改成 `sys.executable` fallback, 不依赖 .venv |

#### 3.5.7 防火墙放行 (同事访问前提)

Windows 防火墙需放行 8080 端口, 同事才能通过 `10.66.67.26:8080` 访问:

```powershell
# 以管理员运行 PowerShell
New-NetFirewallRule -DisplayName "Automation Platform Frontend" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

## 4. 数据备份与恢复

### 4.1 MySQL 备份

```powershell
# 默认备份到 data/backups/
powershell -ExecutionPolicy Bypass -File scripts/backup_mysql.ps1

# 指定输出目录
.\scripts\backup_mysql.ps1 -OutputDir D:\backups
```

脚本调用容器内 `mysqldump` 导出 SQL 到 `data/backups/automation-<timestamp>.sql`.

### 4.2 MySQL 恢复

```powershell
# 必填: 指定备份文件
powershell -ExecutionPolicy Bypass -File scripts/restore_mysql.ps1 -BackupFile data\backups\automation-20260823-100000.sql
```

### 4.3 备份策略建议

| 频率 | 范围 | 保留期 |
| --- | --- | --- |
| 每日 | MySQL 全量 dump | 7 天 |
| 每周 | 整个 `data/mysql/` 目录 | 4 周 |
| 重大变更前 | 手动备份 | 永久 |

可用 Windows 任务计划程序定时执行 `backup_mysql.ps1`.

## 5. 镜像管理

### 5.1 MySQL 镜像导出

防止 Docker Desktop 重装或镜像 GC 丢失:

```powershell
# 默认导出到 data/docker-images/mysql-8.4.tar
powershell -ExecutionPolicy Bypass -File scripts/save_mysql_image.ps1
```

如本地无 MySQL 镜像, 脚本会先从 `mirror.gcr.io` 拉取并打 tag.

### 5.2 镜像恢复

```powershell
docker load -i data\docker-images\mysql-8.4.tar
```

### 5.3 GitLab 镜像

GitLab CE 镜像独立备份至 `C:/docker-data/git-server/images/gitlab-ce-latest.tar`.
详见 `docs/GitLab本地部署.md`.

### 5.4 测试管理平台镜像备份

防止 Docker Desktop 重装或镜像 GC 丢失测试管理平台相关镜像 (重建一次要拉基础镜像+装依赖, 国内拉 docker.io 又慢又容易断):

```powershell
# 一键备份 5 个镜像到 data/docker-images/
powershell -ExecutionPolicy Bypass -File scripts/save_platform_images.ps1
```

默认备份列表:

| 镜像 | tar 文件 | 大小 |
| --- | --- | --- |
| `automation-platform-backend:latest` | `automation-platform-backend_latest.tar` | ~375 MB |
| `automation-platform-frontend:latest` | `automation-platform-frontend_latest.tar` | ~26 MB |
| `python:3.12-slim` | `python_3.12-slim.tar` | ~43 MB |
| `node:20-alpine` | `node_20-alpine.tar` | ~46 MB |
| `nginx:alpine` | `nginx_alpine.tar` | ~26 MB |

自定义备份列表:

```powershell
# 只备份某几个
powershell -ExecutionPolicy Bypass -File scripts/save_platform_images.ps1 -Images @("python:3.12-slim", "nginx:alpine")
```

恢复 (Docker 重装或换机器后):

```powershell
# 全部恢复
docker load -i data\docker-images\automation-platform-backend_latest.tar
docker load -i data\docker-images\automation-platform-frontend_latest.tar
docker load -i data\docker-images\python_3.12-slim.tar
docker load -i data\docker-images\node_20-alpine.tar
docker load -i data\docker-images\nginx_alpine.tar

# 然后直接起容器, 不用重新 build
docker compose -f docker/docker-compose.yml up -d mysql backend frontend
```

> 镜像只在代码变更需要重建时才重新 `docker compose build`, 平时重装 Docker 直接 `docker load` 即可.

### 5.5 Dockerfile

项目自带四个 Dockerfile:

| 文件 | 用途 |
| --- | --- |
| `docker/Dockerfile` | 测试运行时镜像: Python 3.12 + uv + framework, 跑测试用 |
| `docker/Dockerfile.ci` | CI 镜像: Python 3.12 + uv + JRE + allure CLI, GitLab/Jenkins 用 |
| `docker/Dockerfile.backend` | 测试管理平台后端镜像: FastAPI + 项目源码 (含 framework+projects), 容器化部署用 |
| `docker/Dockerfile.frontend` | 测试管理平台前端镜像: 多阶段 (node build + nginx 托管), 容器化部署用 |

构建:

```bash
# 测试运行时镜像
docker build -f docker/Dockerfile -t automation-platform:dev .

# CI 镜像
docker build -f docker/Dockerfile.ci -t automation-platform:ci .

# 测试管理平台 (生产模式)
cd docker
docker compose build backend frontend
```

## 7. 常见问题

### 7.1 MySQL 容器无法启动

```bash
# 看错误日志
docker compose -f docker/docker-compose.yml logs mysql

# 常见原因:
# 1. data/mysql/ 权限不对 (Linux 上需要 chown 999:999)
# 2. 3306 端口被占用 (netstat -ano | findstr 3306)
# 3. data/mysql/ 旧数据版本不兼容 (删 data/mysql/ 重建, 但会丢数据)
```

### 7.2 后端连不上 MySQL

```bash
# 1. 检查容器健康状态
docker compose -f docker/docker-compose.yml ps mysql

# 2. 测试连通性
docker exec -it <mysql_container> mysql -utester -ptesterpw -e "SELECT 1"

# 3. 检查 APP_DATABASE_URL 环境变量
echo $env:APP_DATABASE_URL

# 4. 查看后端日志
# /api/health 返回的 database 字段应为 "connected"
```

### 7.3 端口冲突

| 端口 | 服务 | 占用时处理 |
| --- | --- | --- |
| 3306 | MySQL | 改 docker-compose.yml ports |
| 6379 | Redis | 改 docker-compose.yml ports |
| 9092 | Kafka | 改 docker-compose.yml ports |
| 8900 | 后端 (本地进程或容器) | 改 docker-compose.yml ports 或 `start_backend.ps1 -Port` |
| 5173 | 前端 (本地 vite dev) | `start_frontend.ps1 -Port 其他端口` |
| 8080 | 前端 (容器 nginx 生产模式) | 改 docker-compose.yml ports |
| 8929 | GitLab | 改 docker/gitlab/docker-compose.yml ports |
| 2224 | GitLab SSH | 同上 |

### 7.4 Docker Desktop 升级后容器消失

容器配置已 `restart: unless-stopped`, 升级 Docker Desktop 后会自动恢复.
如未恢复:

```bash
docker compose -f docker/docker-compose.yml up -d
cd docker/gitlab && docker compose up -d
```

### 7.5 数据丢失?

| 位置 | 是否持久化 | Docker 升级会丢吗 |
| --- | --- | --- |
| `data/mysql/` | 项目本地挂载 | 不会 |
| `C:/docker-data/git-server/` | 系统目录挂载 | 不会 |
| Redis 数据 | Docker named volume | 通常不会 |
| Kafka 数据 | Docker named volume | 通常不会 |
| 容器日志 | 容器内 | 容器删除即丢 |

> 建议: 重要数据 (MySQL) 定期用 `backup_mysql.ps1` 导出 SQL 备份.
