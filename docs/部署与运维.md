# 部署与运维

> 项目基础设施的部署/启动/备份/恢复说明. 覆盖 Docker 测试依赖、测试管理平台
> 一键启动、镜像导出与数据持久化.

## 1. 基础设施清单

| 服务 | 用途 | 端口 | 数据持久化 |
| --- | --- | --- | --- |
| MySQL 8.4 | 测试管理平台元数据库 | 3306 | `data/mysql/` |
| Redis 7.4 | 缓存测试 (框架能力) | 6379 | Docker named volume |
| Kafka 3.9 | 消息队列测试 (框架能力) | 9092 | Docker named volume |
| GitLab CE | 部门协同 Git 服务器 | 8929 / 2224 | `C:/docker-data/git-server/` |
| FastAPI | 测试管理平台后端 | 8900 | - |
| Vite | 测试管理平台前端 | 5173 | - |

> GitLab 部署独立于本项目, 详见 `docs/GitLab本地部署.md`.

## 2. Docker 测试依赖

### 2.1 docker-compose 配置

文件: `docker/docker-compose.yml`, 包含 MySQL / Redis / Kafka 三个服务.

```bash
# 启动全部
docker compose -f docker/docker-compose.yml up -d

# 启动单个
docker compose -f docker/docker-compose.yml up -d mysql

# 停止
docker compose -f docker/docker-compose.yml down

# 看状态
docker compose -f docker/docker-compose.yml ps
```

### 2.2 MySQL 数据持久化

MySQL 数据目录绑定到项目本地 `data/mysql/`:

```yaml
volumes:
  - ../data/mysql:/var/lib/mysql
```

**关键点**:
- Docker Desktop 更新、卸载或容器重建**不会删除**该目录
- `data/mysql/` 已被 `.gitignore` 忽略, 不会进 Git
- 容器首次启动会自动创建数据库 `automation` 与用户 `tester`

### 2.3 默认凭据

| 项 | 值 | 说明 |
| --- | --- | --- |
| Root 密码 | `rootpw` | 仅本地用, 不要暴露到生产 |
| 业务数据库 | `automation` | 测试管理平台用 |
| 业务用户 | `tester` / `testerpw` | 仅授予 automation 数据库权限 |

可通过环境变量覆盖 (见 `.env.example`):

```
MYSQL_ROOT_PASSWORD=rootpw
MYSQL_DATABASE=automation
MYSQL_USER=tester
MYSQL_PASSWORD=testerpw
```

### 2.4 连接 URL

测试管理平台后端默认用:

```
mysql+aiomysql://tester:testerpw@127.0.0.1:3306/automation
```

可通过环境变量 `APP_DATABASE_URL` 覆盖.

## 3. 测试管理平台启动

### 3.1 一键启动 (推荐)

```powershell
# 在项目根目录执行
powershell -ExecutionPolicy Bypass -File scripts/start_all.ps1
```

脚本自动完成:
1. 检查并加载 MySQL 离线镜像 (`data/docker-images/mysql-8.4.tar`)
2. 启动 MySQL 容器并等待健康检查
3. 启动 FastAPI 后端 (`uvicorn server.main:app --port 8900`)
4. 启动 Vite 前端 (`npm run dev --port 5173`)
5. 轮询 `/api/health` 确认后端就绪
6. 输出访问地址

强制 `chcp 65001` + UTF-8 输出, 避免中文乱码.

### 3.2 分进程启动

如需单独调试前后端, 分别开两个 PowerShell 终端:

```powershell
# 终端 1: 后端
powershell -ExecutionPolicy Bypass -File scripts/start_backend.ps1

# 终端 2: 前端
powershell -ExecutionPolicy Bypass -File scripts/start_frontend.ps1
```

参数支持:

```powershell
.\scripts\start_backend.ps1 -Port 8900
.\scripts\start_frontend.ps1 -Port 5173
```

### 3.3 访问入口

| 入口 | 地址 |
| --- | --- |
| 前端工作台 | http://localhost:5173 |
| 后端 API 文档 (Swagger) | http://localhost:8900/docs |
| 健康检查 | http://localhost:8900/api/health |

### 3.4 首次部署

```powershell
# 1. 克隆代码
git clone <repo-url> automation-platform
cd automation-platform

# 2. Python 依赖
uv sync                       # 创建 .venv + 安装 framework + 全部依赖
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt

# 3. 前端依赖
cd frontend
npm install
cd ..

# 4. (可选) 准备 MySQL 离线镜像
.\scripts\save_mysql_image.ps1    # 导出 mysql-8.4.tar 到 data/docker-images/

# 5. 一键启动
.\scripts\start_all.ps1
```

## 4. 数据备份与恢复

### 4.1 MySQL 备份

```powershell
# 默认备份到 data/backups/
powershell -ExecutionPolicy Bypass -File scripts/backup_mysql.ps1

# 指定输出目录
.\scripts\backup_mysql.ps1 -OutputDir D:\backups
```

脚本调用容器内 `mysqldump` 导出 SQL 到 `data/backups/automation-<timestamp>.sql`.

### 4.2 MySQL 恢复

```powershell
# 必填: 指定备份文件
powershell -ExecutionPolicy Bypass -File scripts/restore_mysql.ps1 -BackupFile data\backups\automation-20260823-100000.sql
```

### 4.3 备份策略建议

| 频率 | 范围 | 保留期 |
| --- | --- | --- |
| 每日 | MySQL 全量 dump | 7 天 |
| 每周 | 整个 `data/mysql/` 目录 | 4 周 |
| 重大变更前 | 手动备份 | 永久 |

可用 Windows 任务计划程序定时执行 `backup_mysql.ps1`.

## 5. 镜像管理

### 5.1 MySQL 镜像导出

防止 Docker Desktop 重装或镜像 GC 丢失:

```powershell
# 默认导出到 data/docker-images/mysql-8.4.tar
powershell -ExecutionPolicy Bypass -File scripts/save_mysql_image.ps1
```

如本地无 MySQL 镜像, 脚本会先从 `mirror.gcr.io` 拉取并打 tag.

### 5.2 镜像恢复

```powershell
docker load -i data\docker-images\mysql-8.4.tar
```

### 5.3 GitLab 镜像

GitLab CE 镜像独立备份至 `C:/docker-data/git-server/images/gitlab-ce-latest.tar`.
详见 `docs/GitLab本地部署.md`.

### 5.4 Dockerfile

项目自带两个 Dockerfile:

| 文件 | 用途 |
| --- | --- |
| `docker/Dockerfile` | 应用镜像: Python 3.12 + uv + framework, 跑测试用 |
| `docker/Dockerfile.ci` | CI 镜像: Python 3.12 + uv + JRE + allure CLI, GitLab/Jenkins 用 |

构建:

```bash
# 应用镜像
docker build -f docker/Dockerfile -t automation-platform:dev .

# CI 镜像
docker build -f docker/Dockerfile.ci -t automation-platform:ci .
```

### 6.1 后端日志

FastAPI 通过 uvicorn 输出到 stdout, 直接在终端可见. 当前未持久化, 后续可接入


## 7. 常见问题

### 7.1 MySQL 容器无法启动

```bash
# 看错误日志
docker compose -f docker/docker-compose.yml logs mysql

# 常见原因:
# 1. data/mysql/ 权限不对 (Linux 上需要 chown 999:999)
# 2. 3306 端口被占用 (netstat -ano | findstr 3306)
# 3. data/mysql/ 旧数据版本不兼容 (删 data/mysql/ 重建, 但会丢数据)
```

### 7.2 后端连不上 MySQL

```bash
# 1. 检查容器健康状态
docker compose -f docker/docker-compose.yml ps mysql

# 2. 测试连通性
docker exec -it <mysql_container> mysql -utester -ptesterpw -e "SELECT 1"

# 3. 检查 APP_DATABASE_URL 环境变量
echo $env:APP_DATABASE_URL

# 4. 查看后端日志
# /api/health 返回的 database 字段应为 "connected"
```

### 7.3 端口冲突

| 端口 | 服务 | 占用时处理 |
| --- | --- | --- |
| 3306 | MySQL | 改 docker-compose.yml ports |
| 6379 | Redis | 改 docker-compose.yml ports |
| 9092 | Kafka | 改 docker-compose.yml ports |
| 8900 | 后端 | `start_backend.ps1 -Port 其他端口` |
| 5173 | 前端 | `start_frontend.ps1 -Port 其他端口` |
| 8929 | GitLab | 改 docker/gitlab/docker-compose.yml ports |
| 2224 | GitLab SSH | 同上 |

### 7.4 Docker Desktop 升级后容器消失

容器配置已 `restart: unless-stopped`, 升级 Docker Desktop 后会自动恢复.
如未恢复:

```bash
docker compose -f docker/docker-compose.yml up -d
cd docker/gitlab && docker compose up -d
```

### 7.5 数据丢失?

| 位置 | 是否持久化 | Docker 升级会丢吗 |
| --- | --- | --- |
| `data/mysql/` | 项目本地挂载 | 不会 |
| `C:/docker-data/git-server/` | 系统目录挂载 | 不会 |
| Redis 数据 | Docker named volume | 通常不会 |
| Kafka 数据 | Docker named volume | 通常不会 |
| 容器日志 | 容器内 | 容器删除即丢 |

> 建议: 重要数据 (MySQL) 定期用 `backup_mysql.ps1` 导出 SQL 备份.
